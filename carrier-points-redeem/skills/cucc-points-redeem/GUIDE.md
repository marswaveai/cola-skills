# 联通积分兑换

共同账户、授权、浏览器、断点和证据规则沿用统一入口。方法与商城分开处理，不用商城积分余额判断短信话费可兑性。

## 话费（短信方法）

明确问话费方法或选择话费时，直接输出入口 [SKILL.md](../../SKILL.md) 「联通：直接给短信领取方式」一节的感谢及指定文案。不需要手机号，不登录、不发短信、不生成二维码、不调用其他短信技能；具体规则以本次 `10010` 回复为准。混合请求再继续下面的商城流程。

## 查询与选品

1. **登录直达**：<https://uac.10010.com/portal/mallLogin.jsp?redirectURL=https://img.client.10010.com/jifenshangchengpc/index.html#/>。新任务默认未登录，直接打开此完整地址；看到“密码登录 / 随机密码登录”表单就交接本人完成手机号、密码/随机码和拼图。登录后回积分商城，不先访问商城查登录态。
2. 等业务数据加载，核对脱敏号码，分别读取通信积分、奖励积分及可见到期信息。初始 0 或“通讯积分不足”不直接当结果；两类积分按商品适用条件分别判断，不能简单相加。
3. 已明确流量/语音/影音用途时直接筛选；已指定商品时定位该商品，不先遍历全目录。泛问“能换什么”时逐页取少量余额内候选，需要更多再展开；“我能兑换”只作候选来源，不保证资格。另用一句话提示话费可走 10010 文字方法，用户需要完整指令时再输出入口里的文字。
4. 只对候选补读详情及 [类别规则](references/redemption-types.md) 的对应部分。核对完整组合、所需积分、现金、有效期、续订、号码和第三方账号限制，列少量编号候选。影音组合不能简写成纯视频会员；具体条款要求本人操作时交接该步，不把限制扩大到整个类别。
5. 查询保持只读。明确选定兑换后办理；未给数量按 1 份，不默认兑光积分。“试兑一次”但没选商品时，先给最低积分候选的内容、期限和成本供选择，不自行扣分。

## 准备与提交

1. 只办本机、现金 0、无自动续订、关键规则已核实的流量包、语音包或影音组合。找不到符合条件的商品就报告实际情况。
2. 在回复中记下商品类别、ID、完整组合、期限和续订条件，以及可能建单/扣分前的阶段；同一笔沿用本对话记录。
3. 选“积分购买”，读取真实确认订单，将账户、商品 ID/名称、完整内容、数量、适用积分、现金及有效期与授权核对。规格或成本变化时说明新条件，不沿用旧方案继续。
4. 已授权且订单核对通过时，如需积分扣减验证码，只请求一次；记录阶段并交接同一订单页，让本人填写。倒计时只代表请求动作，不证明收到；不读验证码输入值。
5. 本人确认后先读当前阶段：成功/订单详情/处理中只对账；仍是同一确认订单、验证完成且条件未变，才按原授权提交一次。若官网要求本人同时确认，由本人完成后接回；阶段不明先查订单。
6. 最终按钮点击前更新提交断点；异常、超时或处理中不重提。复杂恢复需要本地脚本时才读 [提交保护](references/transaction-state.md)，正常流程不运行脚本。

## 核对与恢复

- 用官网入口核对本笔订单、实际扣分、现金及接收账户；成功页若尚无订单号继续只读查原订单。处理中按页面建议有限复查，保留下一步，不新建同笔交易。
- 分别记录平台订单完成与实际权益到账；运营商/第三方开通明细才能作为对应独立核验，用户确认单独注明。未知余额不推算。
- 页面身份错位、弹新页或失败恢复时才读 [页面线索](references/browser-flow.md)。结果按统一入口汇报。

实测边界：2026-10-20 覆盖登录、余额/目录、结算、验证码请求和 1GB 日包订单完成及扣分；接回时已是成功页，Agent 最终按钮点击未实测，语音/影音未完成真实兑换。不把流程支持说成所有类别均已跑通。
